## Слайд 2 — Введение в предметную область

**Заголовок:** Введение в предметную область

**Содержание:**

**Longest Common Subsequence (LCS)** — наибольшая общая подпоследовательность
двух строк. Подпоследовательность получается удалением некоторых элементов без
изменения порядка оставшихся.

**Константа Чватала-Санкоффа γ_k** (1975): Для двух случайных строк длины n
над алфавитом размера k:

    E[LCS(X,Y)] / n → γ_k при n → ∞

**Открытая проблема:** Точные значения γ_k неизвестны с 1975 года ни для одного k!

**Наиболее изученный случай — бинарный алфавит (k=2):**
- Нижняя: γ₂ ≥ 0.792666 (Heineman et al., 2024)
- Верхняя: γ₂ ≤ 0.826280 (Lueker, 2009)
- Эмпирическая: γ₂ ~ 0.811 (Монте-Карло)

**Иллюстрация справа:** Пример LCS("ABCD", "ACBD") = "ABD" (длина 3)

> Фокус на бинарном алфавите как основном объекте.
> γ₄ не упоминается — появится позже как дополнительный результат.

**Заголовок:** Цели и задачи исследования

**Цель работы:**

5. Сравнить полученные оценки с лучшими известными из литературы
6. Исследовать применимость метода к другим размерам алфавита

> Цель сфокусирована на γ₂. Задача 6 намекает на обобщение (γ₄),

## Слайд 5 — Предпосылки решения

**Заголовок:** Предпосылки решения

**Содержание:**

**Основная идея:**
Для получения нижней оценки можно считать E[LCS] для «кусочков» строк.

Примеры (полный перебор, k=2):
- Для кусков длины 1: E/n = 0.5
- Для кусков длины 2: E/n = 0.5625
- Для кусков длины 10: E/n = ...

Полный перебор работает за O(2^(2n) · n²), для больших кусков нужно
придумать что-то ещё...

**Ключевая идея:** Генерировать строки «на ходу», видя только N символов вперёд.
Любая стратегия с ограниченным обзором даёт валидную нижнюю оценку!

**Иллюстрация 1 (верх):** Разбиение строки на куски, для каждого считается E[LCS],
                          общее E ≥ сумма по кускам

**Иллюстрация 2 (низ):** Две строки a и b с указателями, окна обзора N символов
                         вперёд от текущей позиции, сдвиг между позициями

> Без существенных изменений, иллюстрации сохраняются.

## Слайд 6 — Описание метода

**Заголовок:** Описание метода: Динамическое программирование с окнами

**Содержание:**

**Состояние DP:**
solve(L, shift, maskA, maskB)
- L — оставшаяся длина строк
- shift — текущий сдвиг |i − j| между позициями в строках A и B
- maskA, maskB — содержимое окон обзора (следующие N символов)

**Возвращает:** E[LCS] для данной конфигурации

**Таблица переходов динамики:**

| Что делаем | Условие | L | Shift |
|------------|---------|---|-------|
| Двигаем вперёд a | shift > 0 | -= 1 | -= 1 |
| Меняем a и b | shift == 0 | const | = 1 |
| Двигаем вперёд b | shift < MAX_SH | const | += 1 |
| Также двигаем и a | shift == MAX_SH | -= 1 | const |
| **Берём символ в LCS** | **maskA[0] == maskB[0]** | **-= 1** | **const** |

**Сложность:** Время O(K · MAX_SH · 2^(2N)), Память O(MAX_SH · 2^(2N))

**Иллюстрация 1 (лев):** Состояние DP: строки a, b, окна maskA/maskB, сдвиг shift
**Иллюстрация 2 (прав):** Переход: продвинули a, новая maskA, shift уменьшился на 1

> Метод описан для бинарного случая (как в оригинале).
> Сложность через 2^(2N) — для бинарного алфавита.
> Обобщение на k=4 упоминается на слайде доп. результатов.

## Слайд 7 — Оптимизации реализации

**Заголовок:** Оптимизации реализации

**Содержание:**

**Вычислительные оптимизации:**

1. **Итеративный подход:**
   - Замена рекурсии на итерацию по L от 1 до K
   - Избегание overhead вызовов функций

2. **Оптимизации компилятора:**
   - -Ofast, -funroll-loops, -ffast-math
   - AVX2 (для x86), -mtune=native

3. **float вместо double:**
   - 2x экономия памяти, быстрее в кэше

**Параметры для лучшего результата (k=2):**

| Параметр | Значение |
|----------|----------|
| N (окно) | 12 бит |
| MAX_SH (макс. сдвиг) | 30 |
| K (длина строк) | 40 000 |
| Пар масок | 2^12 × 2^12 = 16.8M |
| Время вычисления | ~6 часов |
| **Результат** | **γ₂ ≥ 0.7964** |

**Справа:** фрагмент кода (основной цикл DP)

> Таблица параметров — только для k=2 (основной результат).
> Параметры k=4 вынесены на слайд доп. результатов.

## Слайд 8 — Дополнительные результаты

**Заголовок:** Дополнительные результаты: алфавит k=4 и верификация

**Содержание (две колонки):**

**Левая колонка — Обобщение на k=4:**

Метод напрямую обобщается на произвольный размер алфавита:
- Для k=4: каждый символ = 2 бита, маска = 2N бит
- Пространство состояний: 4^N × 4^N (вместо 2^N × 2^N)

| Авторы | Год | Нижняя оценка γ₄ |
|--------|-----|-------------------|
| Lueker / Kiwi & Soto | 2009 | ≥ 0.5992 |
| Heineman et al. | 2024 | ≥ 0.6143 |
| **Данная работа** | **2025** | **≥ 0.6230** |

Параметры: N=5, SH=40, K=5000, время ~10 мин.

**Правая колонка — Верификация (Монте-Карло):**

Независимая проверка: пары случайных строк длины n,
точный LCS алгоритмом O(n²), усреднение E[LCS]/n.

| Алфавит | γ (Монте-Карло) | Наша оценка | Зазор |
|---------|-----------------|-------------|-------|
| k=2 | ~0.811 | 0.7964 | 0.014 |
| k=4 | ~0.653 | 0.6230 | 0.030 |

(n=20 000, 1000 испытаний)

Нижние оценки < эмпирики — результаты непротиворечивы.

> Объединены γ₄ и Монте-Карло в один слайд «дополнительных результатов».
> Это экономит место и подчёркивает, что γ₂ — основной вклад.
